# 문제 기록

앱이 기대와 다르게 동작했을 때 원인과 수정을 남기는 곳이다. 문제 하나에 파일 하나를 만든다.

커밋 메시지는 "무엇을 고쳤는지"를, 이 폴더의 문서는 "왜 그랬는지와 다시 생기지 않게 무엇을 했는지"를 남긴다.

## 절차

1. **기록한다.** 증상, 기기·렌더러·앱 버전(커밋), 재현 순서를 적는다. 설정 탭의 디버그 로그에서 관련 줄(`DLNA_`, `UPNP_SOAP`, `PROXY`, `PLAYER` 태그)을 함께 남긴다.
2. **재현한다.** 가능하면 실패하는 자동 테스트로 재현한다. 실기기에서만 재현되면 그 사실과 재현 순서를 남긴다.
3. **고친다.** 수정은 별도 커밋(`fix: ...`)으로 하고, 2번의 테스트가 통과하게 한다.
4. **문서를 쓴다.** 이 폴더에 `YYYY-MM-DD-짧은-이름.md` 파일을 아래 양식으로 만든다.
5. **렌더러 문제면** `docs/dlna-compat.md`의 해당 행도 고친다.

## 양식

```markdown
# <한 줄 제목>

- **발견일**: YYYY-MM-DD
- **영향**: <무엇이 안 되었나. 어느 기기·렌더러에서>
- **증상**: <보인 현상과 재현 순서>
- **원인**: <왜 그랬나>
- **수정**: <커밋 해시와 바꾼 내용 한두 줄>
- **추가한 테스트**: <테스트 파일과 이름. 없으면 이유>
- **재발 방지**:
  - [ ] <남은 할 일이 있으면 적는다. 없으면 "없음">
```

## 관련 문서

- `docs/failure-scenarios.md`: 실기기에서 장애 상황을 확인하는 점검표. 점검 결과가 기대와 다르면 이 절차로 온다.
- `docs/dlna-compat.md`: 렌더러별 재생 결과.
