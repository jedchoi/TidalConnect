# 실기기 장애 상황 점검표

스피커나 네트워크에 문제가 생겼을 때 앱이 어떻게 반응해야 하는지를 실기기에서 확인하는 목록이다.

## 언제 해 보는가

정해진 주기는 없다. 다음 경우에 해 본다.

- 새 렌더러를 시험할 때 (`docs/dlna-compat.md`에 행을 추가할 때 함께)
- 재생 경로를 고친 뒤: `lib/features/player/data/`, `lib/features/dlna/data/`, `android/app/src/main/kotlin/` 의 프록시·플레이어 코드

모두 해 볼 필요는 없다. 고친 부분과 관련된 항목만 해도 된다.

## 점검 항목

| # | 해 볼 것 | 기대 동작 | 자동 테스트가 고정한 부분 |
| --- | --- | --- | --- |
| 1 | 스피커로 재생하는 중에 스피커 전원을 끈다 | 약 6~7초 안에 "스피커가 응답하지 않습니다" 안내가 나오고 재생 표시가 정지로 바뀐다 | `dlna_backend_test.dart` [DB-27] |
| 2 | 스피커로 재생하는 중에 폰의 Wi-Fi를 끈다 | 1번과 같은 안내가 나온다. 그 상태에서 다른 곡을 누르면 Wi-Fi 연결을 확인하라는 안내가 나온다 | [DB-27], [DB-06] |
| 3 | 재생하지 않는 상태에서, 선택해 둔 스피커를 끄고 설정 탭에서 기기 탐색을 한다. 스피커를 다시 켜고 다시 탐색한다 | 폰 스피커로 바뀌고 "…을(를) 찾지 못해 폰 스피커로 전환했습니다" 안내가 나온다. 다시 탐색하면 그 스피커가 자동으로 선택된다 | `dlna_manager_test.dart` [DM-26], [DM-29] |
| 4 | 스피커 재생을 일시정지하고 오래 두었다가 재개한다 (TIDAL 주소의 만료 시간은 확인하지 못했다. 1시간 이상 둔다) | 재생이 이어진다. 주소가 만료되었으면 새 주소를 받아 다시 재생한다 | [DB-48] (Dart 쪽 재발급 응답만) |
| 5 | 스피커의 버튼이나 리모컨으로 재생을 멈춘다 | 앱의 재생 표시가 정지로 바뀌고 다음 곡으로 넘어가지 않는다 | [DB-25] |
| 6 | 화면을 끈 채 스피커 재생을 30분 둔다 | 끊기지 않는다 | [DB-07], [DB-31] (Wi-Fi 잠금을 켜고 끄는 호출만) |
| 7 | 재생 중에 앱을 최근 앱 목록에서 밀어낸다 | 재생이 멈춘다 | `wave_audio_handler_test.dart` [WA-07] |

"자동 테스트가 고정한 부분"은 앱의 Dart 코드가 그렇게 동작한다는 것까지만 확인한다. 실제 스피커와 네트워크에서 그대로 되는지는 이 점검표로만 확인할 수 있다.

## 결과 기록

- 기대대로 동작하면 `docs/dlna-compat.md`의 해당 렌더러 행 비고에 확인한 항목 번호와 날짜를 적는다. 예: `장애 점검 1·3·5 확인 (2026-11-20)`
- 기대와 다르게 동작하면 `docs/incidents/README.md`의 절차를 따른다.
