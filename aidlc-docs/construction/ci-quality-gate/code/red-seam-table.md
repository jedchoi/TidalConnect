# 테스트 경계 표 (RED) - ci-quality-gate

상태: **최종본. 질문 없음, 사람 승인 대기 (관문 1)**. 질문 Q1 ~ Q15 는 2026-11-17 에 모두 권고안으로 정해졌고, 계획 파일의 "규칙 보완" 표에 반영되었다 (4절).

- 기준: `plans/ci-quality-gate-code-generation-plan.md` 의 GT-01 ~ GT-13, P-GT-1 ~ P-GT-5 와 그 아래 "규칙 보완 (2026-11-17)" 표, `nfr-requirements.md` 의 NFR-01-C1 ~ C6, NFR-07-C1 ~ C4, 4절
- 경계: `tool/coverage_gate.dart` 뼈대의 공개 시그니처와 문서 주석 (`parseLcov`, `evaluateCoverage`, `formatReport`, `runCoverageGate`, 타입 3개, 상수 2개). 본문은 보지 않았다 (뼈대라 빈 결과뿐이다)
- 테스트 파일: `test/tool/coverage_gate_test.dart` 하나. `import '../../tool/coverage_gate.dart';`. 생성기와 lcov 를 만드는 도우미도 이 파일 안에 둔다
- 테스트 이름 맨 앞에 `[GT-01]`, `[P-GT-1]` 형식. `main()` 첫머리에서 `configurePbt()`

## 1. 표를 읽는 법

- **행 하나가 테스트 하나다.** 경계값은 한 테스트 안의 표 (입력 → 기대값 목록) 로 묶는다
- 규칙 하나가 경계 두 곳에 걸치거나 (GT-04, GT-10) 서로 다른 문장을 여럿 담고 있으면 (GT-09) 행을 ① ② ③ 으로 나눴다. 같은 ID 로 테스트가 여러 개인 선례는 `dlna_manager_test.dart` 의 `[DM-04]` 다. 나누는 것이 싫으면 알려 주면 합친다
- 기대값은 규칙 문서의 숫자를 손으로 옮긴 리터럴이다. 테스트 안에서 식으로 계산하지 않는다
- "뼈대 예상" 은 지금 뼈대 (`parseLcov` → `[]`, `evaluateCoverage` → 대상 0개라 `passed == true`, `formatReport` → `''`, `runCoverageGate` → `1`) 에서의 결과다
- 뼈대는 `targets` 가 비어 있으므로, `result.targets[0]` 처럼 바로 꺼내면 테스트 쪽 `RangeError` 가 나서 RED 로 인정되지 않는다. **모든 `evaluateCoverage` 테스트는 먼저 `expect(result.targets, hasLength(n))` 을 단언한 뒤 원소를 본다**
- 표기: `rec(경로, h/t)` = 도우미가 만드는 lcov 기록 하나. `SF:경로`, `DA:1,1` … (앞의 h 줄은 횟수 1, 나머지 t−h 줄은 횟수 0), `end_of_record`. 도우미는 문자열을 이어 붙이기만 한다

### 2.3 `formatReport`

`GateResult` · `TargetResult` 를 테스트가 직접 만든다 (`evaluateCoverage` 를 거치지 않는다). 공통 입력 R1:

```
GateResult(thresholdPercent: 80, targets: [
  TargetResult(target: 'lib/b.dart', hitLines: 4,   totalLines: 5,    passed: true,  missingLines: 0),
  TargetResult(target: 'lib/a.dart', hitLines: 799, totalLines: 1000, passed: false, missingLines: 1),
  TargetResult(target: 'lib/c.dart', hitLines: 0,   totalLines: 0,    passed: false, missingLines: 0),
])
```

이 절의 기대값은 GT-09 · GT-10 의 보완 (줄 수 = 대상 수 + 1, 비율은 소수 한 자리 + `%`, `N줄 부족`, 기록 없는 줄의 `0/0`, 마지막 줄의 `<기준값>%`) 을 따른다. 줄의 글자 배치는 단언하지 않는다.

## 3. 속성 기반 테스트 (5개)

실행 횟수는 모두 100 (`pbt_config.dart` 의 `pbtExamples`), seed 는 `configurePbt()` 의 고정값. 생성기는 `kiri_check` 의 조합 함수로만 만든다.

공통 생성기:

- **경로**: 정해진 조각에서 조합한 서로 다른 경로 (`lib/gen/f_<0~99>.dart` 형태). 공백 · `\` · 줄바꿈 없음
- **줄 기록**: 줄 번호 1 ~ 500 (한 파일 안에서 중복 없음) → 횟수. 횟수는 0 이 셋 중 하나꼴, 나머지는 1 ~ 1000
- **실행 기록**: 파일 0 ~ 6개, 파일마다 줄 0 ~ 40개
- **쓰기**: `SF:` / `DA:줄,횟수` … / `end_of_record`. 줄 번호 0 · 음수, 음수 횟수, 소수는 만들지 않는다 (GT-03 보완: 입력 범위 밖)

| 속성 | 생성하는 입력과 범위 | 확인하는 것 | 횟수 | 뼈대 예상 |
