## 남은 의문

1. **뼈대에서는 규칙별 단언까지 가지 못한다.** 22개 가운데 15개 (행 5 ~ 15, P-GT-2 ~ P-GT-5) 는 "결과가 비어 있음" 을 잡는 앞쪽 단언에서 실패한다. 뒤쪽의 규칙별 기대값이 잘못된 구현을 실제로 잡는지는 이 실행으로 드러나지 않는다. Step 6.3 의 변형 확인이 이것을 본다
2. **테스트가 서로 모순되지 않는지** (22개를 모두 통과하는 구현이 있는지) 는 따로 확인했다. 저장소 밖 임시 폴더에 테스트 파일의 사본과 버리는 용도의 구현을 두고 실행해 22개 통과를 보았고, 그 폴더는 지웠다. 저장소에는 아무것도 남기지 않았고 `tool/coverage_gate.dart` 는 건드리지 않았다. 생성기 (걸러 내기, 중복 없는 목록) 가 100회를 채우는 것도 이때 확인되었다. 이 확인은 테스트를 쓴 쪽이 만든 구현으로 한 것이라, GREEN 의 독립 구현을 대신하지 않는다
3. **P-GT-1 · P-GT-4 의 반례는 축소되지 않고 출력된다** (목록을 맵으로 바꾼 생성기라 `kiri_check` 이 줄이지 못하는 것으로 보인다. 원인은 확인하지 않았다). seed 로 재현은 된다. 반례를 작게 보고 싶으면 생성기 모양을 바꿔야 하는데, 표의 범위는 그대로 둘 수 있다. 지금은 고치지 않았다
4. 행 3 은 하위 경우 5개가 한 테스트라 (가) 에서 멈춘다. (다)(라)(마) 가 각각 실패하는지는 뼈대에서 보이지 않는다 (1번과 같은 이유)
