# 요구사항 (Requirements) - DASH 곡의 탐색 지원 (2차 작업)

작성일: 2026-11-17. 브랜치 `feat/dash-seek` (`main` 의 `f1f1fe1` 에서 시작). 앞 작업 (테스트 보강) 의 `requirements.md` 는 그대로 두고, 이 작업의 요구사항을 이 파일에 적는다. 번호는 앞 작업을 잇는다.

사용자 요청 (2026-11-17): "main 최신으로부터 새로운 브랜치를 따서 DASH 곡의 탐색을 지원하도록 기능을 추가해줘. aidlc를 이용하되 모든 단계는 너의 추천으로 자동승인하면서 빠르게 작업을 진행한다."

진행 방식: 질문 파일을 만들지 않고 권장안으로 정한다. 정한 내용과 버린 대안을 이 문서와 설계 문서에 적는다. 각 stage 의 승인은 "사용자 지시에 따른 자동 승인" 으로 `audit.md` 에 기록한다.

## 배경

DLNA 스피커로 재생할 때 TIDAL 이 곡을 DASH (여러 조각) 로 주면 앱 안의 프록시가 조각을 이어 붙여 하나의 흐름으로 보낸다. 이 흐름은 바이트 위치로 건너뛸 수 없어 지금은 다음 두 가지가 막혀 있다 (`DlnaBackend` 의 `_canSeek = !info.isDash`).

- 재생 화면의 탐색 (seek)
- 출력 기기를 스피커로 바꿀 때 듣던 위치에서 이어 재생 (항상 처음부터 재생됨)

## 기능 요구사항

### FR-10: DASH 곡의 탐색
스피커로 DASH 곡을 재생하는 중 탐색하면 요청한 위치 근처에서 재생이 이어진다. 탐색 단위는 DASH 세그먼트 (보통 몇 초) 다: 요청한 위치가 속한 세그먼트의 처음부터 재생한다.

### FR-11: DASH 곡을 중간 위치에서 시작
시작 위치가 있는 재생 (출력 기기 전환, 일시정지 중 전환 뒤 재생) 에서 DASH 곡도 그 위치 근처에서 시작한다.

### FR-12: 재생 위치 표시
중간에서 시작한 DASH 곡도 재생 화면의 진행 위치가 곡 전체 기준으로 표시되고, 곡 끝 판정 (다음 곡으로 넘어감) 이 지금처럼 동작한다.

### FR-13: 기존 동작 유지
- 단일 파일 곡의 재생 · 탐색은 바뀌지 않는다 (스피커에 SOAP `Seek` 를 보내는 방식 그대로)
- 처음부터 재생하는 DASH 곡의 응답은 바뀌지 않는다
- 갭리스 (다음 곡 미리 등록) 는 탐색 뒤에도 유지된다
- 일시정지 상태에서 탐색하면 일시정지 상태가 유지된다

## 비기능 요구사항

앞 작업의 NFR-01 ~ NFR-05 를 그대로 적용한다.

- NFR-01: 커버리지 검사 (`tool/coverage_gate.dart`, 대상 4개 파일 각 80%) 를 계속 통과한다
- NFR-02: `tool/check.sh` 통과. 실기기 확인은 자동 점검의 완료 기준이 아니지만, 이 기능은 렌더러 동작에 기대는 부분이 있어 **실기기 확인이 필요하다** (아래 위험)
- NFR-03: 새 테스트는 네트워크 · 실기기 · 실제 시간 대기에 의존하지 않는다
- NFR-04: 새 변환 · 계산 로직 (위치 → 세그먼트, 위치 보정) 에 속성 테스트를 쓴다
- 확장 규칙: Security 끔, Resiliency 켬, PBT 켬 (앞 작업과 같음)

## 정한 방식과 버린 대안

**정한 방식: 새 주소로 다시 재생.** 탐색하면 요청한 위치가 속한 세그먼트부터 이어 붙인 흐름을 새 주소로 프록시에 등록하고, 스피커에 그 주소를 다시 재생시킨다. 앱이 "이 흐름은 곡의 몇 초부터인지" (시작 오프셋) 를 알고 스피커가 알려 주는 위치에 더한다.

| 대안 | 버린 이유 |
| --- | --- |
| 이어 붙인 흐름에 바이트 Range 를 지원하고 스피커의 `Seek` 에 맡김 | 스피커가 시간을 바이트로 바꾸는 방식이 렌더러마다 다르고, 조각 중간의 바이트에서 시작하면 재생하지 못하는 렌더러가 있다. 앱이 통제할 수 없다 |
| 프록시에서 조각을 풀어 하나의 FLAC 파일로 다시 만들어 보냄 | 프록시가 컨테이너를 다시 써야 해서 범위가 크다 |

## 위험과 확인하지 못하는 것

- **스피커가 알려 주는 위치의 기준이 렌더러마다 다를 수 있다.** 중간 세그먼트부터 시작한 흐름에서 0초부터 세는 렌더러와, 조각에 적힌 시각 (곡 전체 기준) 을 그대로 알려 주는 렌더러가 있을 수 있다. 첫 위치 응답을 보고 둘 중 어느 쪽인지 판정해 보정한다. 판정이 맞는지는 실기기에서만 확인된다
- 중간 세그먼트부터 시작한 fMP4 흐름을 재생하지 못하는 렌더러가 있을 수 있다. 실기기에서만 확인된다. 결과는 `docs/dlna-compat.md` 에 적는다
- 탐색할 때마다 스피커가 주소를 다시 받아 재생하므로 짧은 끊김이 있다
